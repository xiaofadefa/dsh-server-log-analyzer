# 硬件故障处置手册（部件级）

每条都按 **判定阈值 → 立即动作 → 换件条件 → 证据保全** 写。核心纪律：**先保数据与业务，再谈换件；换件前必须留证。**

## 0. 必须立即停机 / 切业务的清单

- 内存 UCE 连续出现（数据完整性已受影响）；
- 单电源机型的电源失效（无冗余）；
- 风扇失效 + 任何温度相关告警（散热闭环已破）；
- RAID 降级且无热备（数据单点）；
- 过温保护（Thermal Trip）或 thermal shutdown；
- 主板/CPLD/电源时序类告警伴随无法开机；
- 出现"非预期掉电"但无法确认供电侧正常（可能反复掉）。
> 动作顺序：切换业务 → 导出 BMC 日志 → 记录现场（槽位/编号/指示灯）→ 再动手。

## 1. 内存

| 现象 | 阈值 | 动作 |
| --- | --- | --- |
| CE（可纠正） | 单条偶发个位数/天：观察；≥10³/天 或速率上升：换条 | 记录 DIMM 槽位 + rank；核对是否集中在同一 rank |
| UCE（不可纠正） | **立即处置**，同槽位 7 天内 ≥2 次即判劣化 | 导出 SEL → 切业务 → 重启（清 MCE 熔断）→ 换该 DIMM |
| 训练失败 / DIMM 被禁用 | 立即（容量已缺失） | 清 CMOS/NVRAM → 内存重训练 → 换槽复测 → 仍失败换条 |
| 多槽位同时报错 | 视为 CPU 内存控制器/内存供电 | 先测电压与 CPU 安装，不要一次换多条 |

- 换件前必做：`racadm hwinventory` / `dmidecode -t 17` 核对"槽位丝印 ↔ 物理位置"，避免现场插错槽。
- 证据保全：保留原条序列号与 SEL 片段，用于备件返修与批次质量追溯。
- 内存镜像/行备用被消耗（Row Sparing）说明颗粒已劣化，等同 CE 趋势处理。

## 2. 处理器（CPU）

- **MCE/IERR/CATERR**：看 bank 归属（内存控制器 bank → 查内存；cache/内核 bank → 查 CPU）。同一物理 CPU 的 UCE ≥2 次 → 换 CPU。
- **热降频（Throttle/PROCHOT）**：先查散热与进风温度，再判 CPU；不要直接换 CPU。
- **过温（Thermal Trip）**：必须更换散热器（硅脂/扣具/底板）并做满载复测，否则回业务必然复发。
- **缓存错误**：可纠正缓存错误可观察；不可纠正按 CPU 更换。
- 换 CPU 前：升级 BIOS/微码到厂商推荐版本（部分 IERR 是微码问题），记录 CPU 序列号。

## 3. 电源

| 现象 | 判定 | 动作 |
| --- | --- | --- |
| 单 PSU 失效（双电机型） | 降级可运行 | 记录槽位与功率，尽快换件；换前禁止拔插另一路 |
| 单 PSU 机型失效 | 业务中断级 | 立即切业务、备件更换 |
| 冗余丢失 | 高风险 | 先恢复冗余（插回/换件），恢复前禁止单路维护 |
| 输入丢失（AC Lost）/整机掉电 | **不是服务器故障** | 查 PDU/UPS/空开；多台同现即机房供电事件 |
| 电压越限（VLT） | 需定位 | 同时看 PSU 与主板 VRM；VBAT/3.3V_STBY 异常优先处理 |
| PSO/Power Unit 事件 | 整机掉电级 | 与 OS 重启时间对齐判断因果 |

- 电源类告警的**第一动作永远是确认供电侧**（尤其"一次掉了一批机器"）。
- 换电源前记录：槽位、额定功率、型号、固件版本（部分机型要求固件一致）。
- 换完必须确认 BMC 里冗余状态恢复、告警清除。

## 4. 散热与温度

- **风扇失效/被拔**：双风扇机型掉一个 → 剩余全速、可短期运行但必须尽快换；换前记录 FAN 编号与是否支持热插拔。
- **转速偏低（Lower Critical）**：轴承磨损或进灰；同步检查防尘网与线缆遮挡。
- **进风口温度 >27℃**：机房制冷问题，改环境而不是换件。
- **局部高温（内存/芯片组/M.2/HDD）**：导风罩缺失、风道被塞、背板风道异常——搬迁/清灰忘装导风罩是高频人为故障。
- 出现过温保护停机（Thermal Trip/Thermal Shutdown）的机器：更换散热件 + 30 分钟满载温度验证后才允许回业务。

## 5. 硬盘与存储

- **SMART 预警（预测性失效）**：纳入计划更换；SSD 磨损 `Percentage_Used` ≥82% 或备用块耗尽 → 准备更换。
- **硬盘失效**：先看 RAID 是否有热备在重建；**能用热备就直接换，不要先拔盘找备件**。
- **RAID 降级**：必须做备份校验（降级期间的写错误不会被自动修复），重建期间禁止重启/压测/固件升级。
- **RAID 卡/HBA 错误**：先导 TTY/support bundle（`storcli64 /c0 show all`、厂商支持包）再升级固件或换卡；换卡前确认配置导入方法。
- **RAID 卡特有状态（区分"卡自身 / 背板 / 盘"三方责任的关键）**：
  - `Preserved Cache`（保留缓存）：说明 RAID 组曾掉盘/掉电、缓存没落盘 → 先确认该 VD 是否仍在线；**清除保留缓存可能连带删除 RAID 组**，清前必须导 Controller Events + TTY Log（`storcli64 /c0 show preservedCache` → `storcli64 /call/vall delete preservedCache force`）。
  - `Foreign Config`（外部配置）：换卡/换盘/换背板后出现属正常 → 确认这些盘属于本机阵列后用 **Import**（不是 Clear，Clear 丢数据）；人为在线拔盘导致的可用 Unconfigured Good → Import 恢复，不必换盘。
  - `Patrol Read / Consistency Check` 巡检报错增多（media error / uncorrectable）→ 盘在劣化，转硬盘更换评估（结合 `DRIVE_PREDICTIVE` / `DISK_IO_ERROR`）。
  - **取证顺序**：`storcli64 /c0 show all` → `show events`（控制器事件日志）→ `show termlog`（TTY 日志）；**进不去 OS** 时用 RAID 卡管理界面（UEFI/HII → Controller Management）的 **Save Controller Events / Save TTY Log**。
  - 常见卡型写进报修单（华为 V2&V3：LSI SAS2208/2308/3108/3008、华为主控 PM8060/PM8068）—— 不同卡的事件码体系与工具不同。
- **PHY/SAS 链路错误**：单 PHY 反复报错 → 换盘位/线缆；整柜/多盘位同时 → 背板/扩展柜。
- **I/O 超时**：错误计数 + SMART 计数同时增长 → 换盘；仅孤立一次 → 观察。多盘同时超时优先怀疑背板/线缆/HBA。
- **文件系统错误/只读重挂**：先备份再修，不要在业务写入中 fsck。

## 6. PCIe / 插槽 / 网卡

- **AER 不可纠正（Fatal/Non-Fatal）**：记录 BDF（`0000:65:00.0`）→ `lspci -s` 定位 → 重插卡 → 换槽 → 升级卡固件/BIOS → 换卡 → 最后主板。
- **AER 可纠正**：偶发可观察；每秒级刷屏说明链路质量差，做重插/降速/换槽验证。
- **链路降速/降宽**：先确认是否插槽共享或 M.2 占用通道，再查卡与主板协商能力。
- **网卡复位/TX timeout/hang**：升级固件+驱动（厂商推荐组合），再换槽；生产环境先切流量。
- **链路抖动**：>5 次/小时按物理层处理（换线、换光模块、锁速），偶发一次可观察。

## 7. 主板 / 机箱 / BMC

- **主板（PCH/芯片组/主板级错误）**：换板前必须留全"最小化配置复测"证据（1 CPU + 1 DIMM + 无插卡 + 最小电源），否则备件易误换。
- **CPLD/电源时序**：表现为按电源键无反应或随机自动上电 → 按 CPLD 固件/主板更换处理。
- **NVRAM/CMOS 异常**：配置丢失、每次重启恢复默认 → 换 NVRAM/主板，换前导出 BIOS 配置。
- **机箱入侵**：非维护时段出现必须按物理安全事件上报（核对机房出入记录），合法维护后要清状态。
- **BMC 复位/看门狗/传感器失效**：先导出 SEL + 生命周期留证 → 升级 BMC 固件 → BMC 复位 → 仍反复则按主板/BMC 模块更换。
- **SEL 写满**：说明长期存在未闭环告警；导出后归档再清理，并修采集策略。
- **证书/许可过期**：表现为"BMC 网页打不开/Redfish 拒绝连接"，换证书与更新许可即可，不要误判硬件故障。

## 8. 通用纪律

1. **不删证据**：任何 clear/format/reboot 前先导出（SEL、生命周期、支持包）。
2. **一次只动一个变量**：换件、升级、复位不要同时做，否则无法归因。
3. **修完要复测**：内存换条后看 SEL、散热换件后满载温度、RAID 换盘后看重建完成。
4. **闭环要留档**：工单里贴"原始行 + 槽位 + 动作 + 复测结果"，下次同类问题才有对比基线（配合 `hwlog_baseline`/`hwlog_diff`）。
