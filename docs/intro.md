# dsh-server-log-analyzer 是什么

**一句话**：把服务器的带外日志（BMC/iDRAC/iLO/iBMC/XCC/IPMI SEL/Redfish）和系统日志喂给它，
它直接给出**硬件故障初判**——健康评分、分级发现、根因关联、该做的处置动作，以及该敲的命令。

面向的正是运维最难受的场景：**机器出问题、进不去 OS、只有一堆日志**。

---

## 它能回答的四个问题

| 问题 | 它给出的答案 |
| --- | --- |
| 这台机器现在什么状态？ | 健康评分（A/B/C/D）+ 紧急/严重/轻微/提示分级统计 |
| 到底哪里坏了？ | 部件级定位（内存 DIMM、硬盘槽位、PSU 槽位、风扇号、PCIe BDF）+ 事件码解读 |
| 为什么坏？ | 跨源时间对齐做根因关联：是供电侧掉电、机房温度、还是部件自身故障 |
| 现在该干什么？ | 处置动作（换件/观察/先保数据）+ 手册里的取证命令与操作步骤 |

---

## 用起来很简单

**在对话里说一句**（装了插件后）：

> 帮我分析一下 D:\logs\node01 这批日志，先给个结论

**或走命令行**（适合巡检、工单、不想联网的场景）：

```bash
dsh-hwlog analyze .\logs\node01              # 全量报告（Markdown）
dsh-hwlog analyze .\logs\node01 --brief      # 几行摘要
dsh-hwlog collect --brand dell --as-script   # 先生成一键采集脚本
dsh-hwlog baseline .\logs\node01             # 留基线，下次只看变化
dsh-hwlog diff baseline-xxx.json .\logs\node01
```

---

## 三个和"日志关键词搜索"不一样的地方

1. **进不去 OS 也能用。** 只给带外日志（SEL / 一键收集包 / 网页导出 / 甚至二进制 .bin）照样出结论；
   但它会**明确标注**"硬件定性成立、业务影响需另证"，而不是替你编一个业务影响。
2. **不是单条匹配，是跨源因果。** 例如它会把"电源输入丢失"和"OS 侧非预期重启"时间对齐，
   才敢说"掉电来自供电侧（市电/PDU/UPS），不是服务器随机故障"；也会识别"一批机器同时掉电 = 机房事件"。
3. **数据驱动、可扩展，不用改代码。** 厂商手册里的**事件码**和**命令/操作步骤**都抽成外部数据；
   换一版手册、加一个品牌，导入即可生效（自带三个抽取脚本）。

## 它认识什么

- **品牌**：Dell iDRAC、HPE iLO、Lenovo XCC、浪潮 BMC（含其独有的 **IDL 诊断日志**）、华为 iBMC（ALM 告警码）、
  超微、曙光、中兴、H3C、富士通 iRMC、通用 IPMI/Redfish/SEL；
- **故障类别**：内存（CE/UCE）、CPU（MCE/降频）、电源（输入丢失/冗余丢失/模块失效）、散热（风扇/过温）、
  存储与 RAID（降级/重建/预测失效/SMART）、PCIe（AER）、网卡、主板、BMC（看门狗/复位/日志满）、
  固件与安全（TPM/安全启动）；
- **输入形态**：文本/HTML/CSV/JSON 导出、**二进制 SEL**、**GBK 中文导出**、**一键收集 zip**（自动展开）、
  Redfish JSON、syslog/dmesg/journal、smartctl/storcli 输出、浪潮 IDL 日志、华为 ALM 日志。

## 输出长这样（节选）

```
健康评分：0 / 100（D 级 · 危急）—— 立即处置：存在业务中断或数据丢失风险

· [紧急] 内存不可纠正错误（多比特 ECC）  @ DIMM:B1  ×3  语义来源：Dell PowerEdge 错误与事件消息参考
  - 处置动作：记录槽位与事件码后导出 BMC 日志；UCE 立即安排更换该内存条…
  - 相关操作：`storcli64 /c0 show all` / `storcli64 /c0 show events`
· [严重] 电源输入丢失（AC 掉电/输入超范围）  @ PSU:1
  - 根因关联：与 OS 侧"非预期重启"时间对齐 → 掉电来自供电侧（市电/PDU/UPS），不是服务器随机故障
```

---

## 它不做什么（先说清楚）

- **不连设备、不采集、不修改任何东西**：只读你给的日志文件 + 生成采集命令清单，执行与否由你决定；
- **不做"无证据的智能猜测"**：证据不足时它会说"证据不全"，而不会编一个结论；
- **不是监控系统**：没有常驻进程、不做告警推送，是"你来喂日志、它给判断"的模式。

---

## 隐私口径

引擎（解析 / 规则 / 评分 / 报告 / 基线）**100% 本地离线**，代码里没有任何网络请求，也不依赖第三方包。
日志内容是否离开本机，取决于你怎么用：走对话层 → 日志片段会进模型上下文；
只用命令行（`dsh-hwlog analyze <路径> --out 报告.md`）→ 全程不联网。

## 安装

```
dsh plugin --profile desktop add "C:\path\to\dsh-server-log-analyzer-1.0.0.tgz"
```

装完重启 DSH 即可用；详细步骤、验证方法、以及"装完还缺什么"见 `docs/install-for-others.md`。
